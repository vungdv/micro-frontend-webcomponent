# Testing

Write the scenario first, then the code (TDD/BDD).

## 1. Rules

1. **Every change has a test.** Features, fixes and refactors ship with tests. A bug fix adds a test that reproduces the bug.
2. **Test what can be seen.** Assert on outputs: returned state and commands, events sent, DOM in owned elements, logs, spans and metrics. Never on private fields or internal call order.
3. **Fake only the edges.** Fake the network, timers, browser APIs and other apps. Use the real unit and its real collaborators.
4. **No flakiness.** No real network, timers or clock. Every wait is on a fake or an awaited promise.

## 2. Naming

One `it` = one outcome. Name it *given / when / then*, ending with the scenario id:

```js
it('given app A is loading, when the user navigates to B, then A is not mounted [TR-09]', ...)
```

When several tests share setup, group them: `describe('given …')` → `describe('when …')` → `it('then …')`.
